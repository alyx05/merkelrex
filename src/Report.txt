## Task 1: Loading Trading Data and Computing Open-High-Low-Close (OHLC) Data

### i) Explanation

The OHLC (Open-High-Low-Close) engine aggregates raw order book entries from the provided CSV market data files and creates per-day financial summaries for a chosen product. Each entry in the order book contains a timestamp, price, and amount. The engine groups these entries by date and extracts four key price points:
- **Open**: The first trading price of the day
- **Close**: The last trading price of the day
- **High**: The highest price reached during the day
- **Low**: The lowest price reached during the day

This analysis is performed separately for asks and bids, as these represent two sides of the market with independent price dynamics. The user can specify a product (e.g., "ETH/USDT") and optionally filter by a date range.

### ii) Implementation Logic Discussion

The `getOHLC()` method in the `OrderBook` class handles the computation. The process follows these steps:

**Step 1: Filter Orders**
The method filters all orders in the order book based on the specified order type (ask/bid), product name, and optional date range.

**Step 2: Sort Chronologically**
Filtered orders are sorted by timestamp to ensure they are processed in the correct chronological order.

**Step 3: Group by Date**
Orders are grouped using a `std::map<std::string, std::vector<OrderBookEntry>>` where the key is the date string (extracted from the timestamp). The map automatically sorts dates.

**Step 4: Calculate OHLC Values**
For each date group:
- **Open** = price of the first order of the day
- **Close** = price of the last order of the day
- **High** = maximum price among all orders of the day
- **Low** = minimum price among all orders of the day

**Pseudocode:**

```
FUNCTION getOHLC(type, product, startDate, endDate) RETURNS vector<OHLCEntry>

    INITIALIZE filteredOrders AS empty vector

    FOR EACH order IN orderBook DO
        IF order.type != type OR order.product != product THEN SKIP

        SET dateStr = first 10 characters of order.timestamp
        IF startDate not empty AND dateStr < startDate THEN SKIP
        IF endDate not empty AND dateStr > endDate THEN SKIP

        APPEND order TO filteredOrders
    END FOR

    IF filteredOrders IS EMPTY THEN RETURN empty list

    SORT filteredOrders BY timestamp ASCENDING

    INITIALIZE ordersByDate AS std::map<string, vector<OrderBookEntry>>
    FOR EACH order IN filteredOrders DO
        APPEND order TO ordersByDate[date prefix of order.timestamp]
    END FOR

    INITIALIZE ohlcList AS empty vector
    FOR EACH (date, dayOrders) IN ordersByDate DO
        SET open = dayOrders.front().price
        SET close = dayOrders.back().price
        SET high = max price across dayOrders
        SET low = min price across dayOrders
        APPEND OHLCEntry{date, open, high, low, close} TO ohlcList
    END FOR

    RETURN ohlcList
END FUNCTION
```

## Task 2: Login or Register a Trading User Profile

### i) Explanation

The platform enforces authentication before allowing access to trading functionality. Users must either register a new profile or log in with existing credentials. All user data is stored in `USERS_REGISTER.CSV`, and passwords are hashed using `std::hash` for security.

Three authentication paths are available:
1. **Registration**: Create a new user profile with unique credentials and receive a sign-up bonus
2. **Login**: Authenticate using a 10-digit username and password
3. **Password Reset**: Update the password after identity verification

### ii) Implementation Logic Discussion

**Registration Process:**
1. User provides full name, email, and password
2. System checks `USERS_REGISTER.CSV` for duplicates (same full name AND email)
3. A unique 10-digit numeric username is generated
4. Password is hashed using `std::hash<std::string>`
5. User details are saved to `USERS_REGISTER.CSV`
6. A sign-up bonus (5000 USDT) is recorded in `USERS_WALLET.CSV`
7. The bonus is also added to the active in-memory wallet

**Login Process:**
1. User enters their 10-digit username and password
2. System searches `USERS_REGISTER.CSV` for the username
3. If found, the entered password is hashed and compared to the stored hash
4. On success, the user's wallet is loaded from `USERS_WALLET.CSV`

**Password Reset Process:**
1. User provides username and registered email
2. System verifies both match a record in `USERS_REGISTER.CSV`
3. If verified, user enters a new password
4. The new password is hashed and the file is updated

**Pseudocode:**

```
FUNCTION handleRegister()
    INPUT fullName, email, password

    IF userExists(fullName, email) THEN
        PRINT "Account already exists."
        RETURN
    END IF

    // Generate unique 10-digit username
    SET username = ""
    FOR i = 1 TO 10 DO
        username += to_string(rand() % 10)
    END FOR

    SET passwordHash = std::hash<std::string>{}(password)

    // Save to USERS_REGISTER.CSV
    WRITE username, fullName, email, passwordHash TO USERS_REGISTER.CSV
    
    // Record sign-up bonus
    WRITE username, 5000.0 TO USERS_WALLET.CSV
    wallet.insertCurrency("USDT", 5000.0)
    
    PRINT "Your username is: " + username
END FUNCTION

FUNCTION handleLogin() RETURNS bool
    INPUT username, password

    IF loadUser(username, outUser) THEN
        IF std::hash<std::string>{}(password) == outUser.passwordHash THEN
            isLoggedIn = true
            currentUserProfile = outUser
            loadWalletFromFile(username)
            RETURN true
        END IF
    END IF

    PRINT "Invalid credentials."
    RETURN false
END FUNCTION

FUNCTION handlePasswordReset()
    INPUT username, email

    IF loadUser(username, outUser) AND outUser.email == email THEN
        INPUT newPassword
        SET newHash = std::hash<std::string>{}(newPassword)
        REWRITE USERS_REGISTER.CSV replacing this user's hash with newHash
        PRINT "Password updated successfully."
    ELSE
        PRINT "Username and email do not match."
    END IF
END FUNCTION
```

## Task 3: User Wallet & Trading Transactions History

### i) Explanation

This task manages the user's financial state and transaction history. Two CSV files persist this data:
- **USERS_WALLET.CSV**: Stores currency balances per user in the format `username,CUR1:amount1|CUR2:amount2|...`
- **USERS_TRADING.CSV**: Append-only ledger of all transactions in the format `username,timestamp,product,type,price,amount,totalValue`

The system supports:
1. **Wallet Operations**: Depositing and withdrawing funds
2. **Transaction Logging**: Recording all trading activities
3. **Recent Transactions**: Displaying the last 5 transactions
4. **Activity Statistics**: Summarizing trading activity (ask/bid counts, total money spent)

### ii) Implementation Logic Discussion

**Wallet Persistence:**
The `syncWalletFile()` method rewrites `USERS_WALLET.CSV` with the current state of the in-memory wallet. It preserves other users' records while updating only the current user's snapshot.

**Transaction Logging:**
The `logTransaction()` method appends a new record to `USERS_TRADING.CSV` with all relevant trade details, using the current system timestamp.

**Recent Transactions:**
The `showRecentTransactions()` method reads the entire trading file, filters entries for the current user, and displays the last 5 entries in reverse chronological order.

**Activity Statistics:**
The `showUserActivityStats()` method scans the trading file, counting ask and bid sales and calculating total money spent. An optional product filter narrows the analysis.

**Pseudocode:**

```
FUNCTION syncWalletFile()
    READ USERS_WALLET.CSV into lines, keeping other users' records
    
    BUILD current user snapshot from wallet.getBalances()
    
    WRITE all lines + new snapshot to USERS_WALLET.CSV
END FUNCTION

void MerkelMain::syncWalletFile()
{
    // Preserve other users' records
    std::ifstream inFile("src/USERS_WALLET.CSV");
    std::vector<std::string> otherUserLines;
    std::string line;
    while (std::getline(inFile, line)) {
        std::vector<std::string> tokens = CSVReader::tokenise(line, ',');
        if (tokens.size() == 2 && tokens[0] != currentUserProfile.username) {
            otherUserLines.push_back(line);
        }
    }
    inFile.close();

    // Build current user snapshot
    std::map<std::string, double> balances = wallet.getBalances();
    std::ostringstream oss;
    oss << currentUserProfile.username << ",";
    bool first = true;
    for (const auto& balance : balances) {
        if (!first) oss << "|";
        oss << balance.first << ":" << balance.second;
        first = false;
    }

    // Rewrite file
    std::ofstream outFile("src/USERS_WALLET.CSV");
    for (const auto& l : otherUserLines) outFile << l << "\n";
    outFile << oss.str() << "\n";
}
```

## Task 4: Simulating User Trading Activities

### i) Explanation

The simulation engine generates synthetic trading activity to demonstrate the system's capabilities. For each product available in the market data, the engine creates 5 ask orders and 5 bid orders, using realistic price generation based on historical data. This task demonstrates how the system handles large-scale transaction generation and updates the user's wallet accordingly.

### ii) Implementation Logic Discussion

**i. Price Calculation (Justification):**

The simulation calculates prices based on the historical order book to ensure realism without requiring a prediction algorithm. For each product, the engine:
1. Retrieves all historical asks for that product
2. Calculates the minimum (low) and maximum (high) prices from historical data
3. Generates a random factor between 0 and 1
4. Interpolates the simulated price: `price = low + factor × (high - low)`

This approach ensures generated prices remain within realistic bounds while introducing sufficient variety. If no historical data exists, fallback bounds of 10.0 and 100.0 are used.

**ii. Date Gap Management:**

The historical CSV data is from 2020, but the simulation runs in 2026. The engine resolves this by:
1. Using `std::chrono::system_clock::now()` to get the current system time
2. Formatting the time using `std::put_time` to match the CSV timestamp format (`YYYY/MM/DD HH:MM:SS`)
3. Applying this real timestamp to all simulated orders

This ensures all generated transactions carry dates that match the current year (2026) and can be properly analyzed by the OHLC engine.

**iii. Insufficient Balance Handling:**

Before executing each simulated bid, the engine checks:
```cpp
if (!wallet.containsCurrency(quoteCurrency, totalCost)) {
    std::cout << "[SIM SKIPPED] Insufficient " << quoteCurrency << " to place Bid on " << prod << std::endl;
    continue;
}
```

Similar checks are performed for ask orders (checking base currency balance). If funds are insufficient, the order is skipped with a diagnostic message, and the simulation continues to the next transaction.

**Pseudocode:**

```
FUNCTION runTradingSimulation()
    SET simTime = getSystemTimestamp()   // Real 2026 timestamp
    
    FOR EACH product IN orderBook.getKnownProducts() DO
        SET baseCurrency = product.split('/')[0]
        SET quoteCurrency = product.split('/')[1]
        
        SET historicalAsks = orderBook.getOrders(ask, product, earliestTime)
        SET lowPrice = OrderBook::getLowPrice(historicalAsks)   // fallback: 10.0
        SET highPrice = OrderBook::getHighPrice(historicalAsks)  // fallback: 100.0

        // 5 Bid orders
        FOR i = 1 TO 5 DO
            SET factor = (rand() % 100) / 100.0
            SET simPrice = lowPrice + factor * (highPrice - lowPrice)
            SET simAmount = 0.1 + (rand() % 10) / 5.0
            SET totalCost = simPrice * simAmount

            IF NOT wallet.containsCurrency(quoteCurrency, totalCost) THEN
                PRINT "Insufficient " + quoteCurrency + " - skipping"
                CONTINUE
            END IF

            CREATE bidOrder{simPrice, simAmount, simTime, product, bidsale, username}
            wallet.processSale(bidOrder)
            orderBook.insertOrder(bidOrder)
            logTransaction("bidsale", product, simPrice, simAmount)
        END FOR

        // 5 Ask orders (mirror logic, checking baseCurrency balance)
        FOR i = 1 TO 5 DO
            // ... similar price and amount generation ...
            IF NOT wallet.containsCurrency(baseCurrency, simAmount) THEN
                PRINT "Insufficient " + baseCurrency + " - skipping"
                CONTINUE
            END IF
            CREATE askOrder{...}
            wallet.processSale(askOrder)
            orderBook.insertOrder(askOrder)
            logTransaction("asksale", product, simPrice, simAmount)
        END FOR
    END FOR

    syncWalletFile()
    PRINT transactions generated
END FUNCTION
```

void MerkelMain::runTradingSimulation()
{
    std::vector<std::string> products = orderBook.getKnownProducts();
    std::string simTime = getSystemTimestamp();
    int transactionsGenerated = 0;

    for (const std::string& prod : products) {
        // ... parse base/quote currencies ...
        
        // Get historical bounds
        std::vector<OrderBookEntry> historicalAsks = 
            orderBook.getOrders(OrderBookType::ask, prod, orderBook.getEarliestTime());
        double lowPrice = OrderBook::getLowPrice(historicalAsks);
        double highPrice = OrderBook::getHighPrice(historicalAsks);
        
        // Generate 5 bid orders
        for (int i = 0; i < 5; ++i) {
            double factor = (double)(std::rand() % 100) / 100.0;
            double simulatedPrice = lowPrice + (factor * (highPrice - lowPrice));
            double simulatedAmount = 0.1 + ((double)(std::rand() % 10) / 5.0);
            double totalCost = simulatedPrice * simulatedAmount;

            // Insufficient balance check
            if (!wallet.containsCurrency(quoteCurrency, totalCost)) {
                std::cout << "[SIM SKIPPED] Insufficient " << quoteCurrency << std::endl;
                continue;
            }

            // Execute trade
            OrderBookEntry bidOrder{simulatedPrice, simulatedAmount, simTime, prod, 
                                   OrderBookType::bidsale, currentUserProfile.username};
            wallet.processSale(bidOrder);
            logTransaction("bidsale", prod, simulatedPrice, simulatedAmount);
            transactionsGenerated++;
        }
        
        // ... similar for ask orders ...
    }
    
    syncWalletFile();
    std::cout << "Successfully processed " << transactionsGenerated << " transactions." << std::endl;
}

## Task 5: Printing User Interaction Menu

### i) Explanation

The user interaction menu provides the interface for all system features. It supports authentication, trading operations, data analysis, wallet management, and simulation. The menu is designed to be robust, handling incorrect inputs gracefully without abrupt termination.

### ii) Implementation Logic Discussion

**Menu Structure:**

The main menu offers 11 functional options:
1. Print help
2. Print exchange stats
3. Make an offer (ask)
4. Make a bid
5. Print wallet
6. Continue to next timeframe
7. View Product OHLC Data
8. Deposit or Withdraw Funds
9. View Recent Transactions
10. View Activity Summary Statistics
11. Run 2026 Trading Activity Simulator
12. Logout / Exit

**Input Validation Key Measures:**

1. **Line-Based Reading:** All user input is read using `std::getline` rather than `std::cin >>`. This prevents stream state issues and ensures the input buffer is fully consumed regardless of what the user types.

2. **Safe Integer Conversion:** Menu selections are converted using `std::stoi` inside a `try-catch` block. If conversion fails (user enters letters or out-of-range numbers), the option defaults to 0, which is treated as an invalid choice.

3. **Numeric Input Validation:** Amounts for deposits/withdrawals are parsed with `std::stod` in a `try-catch` block, returning early on bad input without modifying the wallet.

4. **Date Validation:** Date inputs for OHLC filtering are validated by checking format and chronological order.

**Pseudocode:**

```
FUNCTION getUserOption() RETURNS int
    PRINT "Type in 1-12"
    READ rawLine VIA std::getline

    SET option = 0
    TRY
        option = std::stoi(rawLine)
    CATCH (any exception)
        option = 0   // Treated as invalid
    END TRY

    RETURN option
END FUNCTION

FUNCTION processUserOption(option)
    IF option == 0 THEN PRINT "Invalid choice. Choose 1-12."
    IF option == 1 THEN printHelp()
    IF option == 2 THEN printMarketStats()
    // ... all valid options ...
    IF option == 11 THEN runTradingSimulation()
    IF option == 12 THEN isLoggedIn = false; RETURN to auth menu
END FUNCTION
```
